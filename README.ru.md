# VPN Stack

> Для параноидального сисадмина, который не доверяет готовым бинарникам, считает «просто используй коммерческий VPN» личным оскорблением и не уснёт, пока каждая строка кода не будет прочитана, каждый ключ не будет сгенерирован на его собственном железе, а каждый пакет не пойдёт ровно туда, куда он сказал. Всё здесь собрано из исходников. Никаких чёрных ящиков. Спите спокойно :smile:

Самостоятельно размещённый VPN-сервер, объединяющий **AmneziaWG** (обфусцированный WireGuard) и **Xray REALITY** (VLESS-прокси), с внутренним DNS-резолвером **dnscrypt-proxy** — всё через Docker Compose.

## Архитектура

```
┌──────────────────────────────────────────────────────┐
│                  Docker network: vpn                 │
│                   172.20.0.0/24                      │
│                                                      │
│  ┌────────────┐  ┌──────────────┐  ┌──────────────┐  │
│  │    DNS     │  │  AmneziaWG   │  │    Xray      │  │
│  │ 172.20.0.2 │  │ 172.20.0.3   │  │ 172.20.0.4   │  │
│  │  DNS :53   │  │ VPN :<rand>  │  │ REALITY :443 │  │
│  │ (internal) │  │   (public)   │  │   (public)   │  │
│  └────────────┘  └──────────────┘  └──────────────┘  │
└──────────────────────────────────────────────────────┘
```

| Сервис        | Роль                                                        | Порт             |
|---------------|-------------------------------------------------------------|------------------|
| **DNS**       | dnscrypt-proxy — шифрует и аутентифицирует DNS-запросы      | 53 (только Docker) |
| **AmneziaWG** | Обфусцированный WireGuard VPN-сервер                        | random/udp       |
| **Xray**      | VLESS + REALITY прокси                                      | 443/tcp          |

Все VPN-клиенты принудительно используют внутренний DNS-резолвер через iptables DNAT — DNS-запросы никогда не покидают сервер бесконтрольно.

## Требования

- Ubuntu **24.04 или новее**
- Root или sudo-доступ
- Docker Engine + Docker Compose plugin (см. ниже)
- Порты **443/tcp** и случайно назначенный **AWG UDP-порт** должны быть открыты в облачном файрволе (AWS Security Group, GCP VPC rules и т.д.)

### Установка Docker

Если Docker ещё не установлен, используйте прилагаемый скрипт:

```bash
sudo ./docker-install.sh
```

Скрипт устанавливает Docker Engine и Docker Compose plugin из официального apt-репозитория Docker. Пропускает уже установленные компоненты и завершается с ошибкой на Ubuntu ниже 24.04.

> Для продакшн-развёртывания также рекомендуется:
> - Настройка файрвола (UFW, iptables или облачный файрвол)
> - Усиление SSH (нестандартный порт, отключение парольной авторизации)
> - fail2ban или аналогичная защита от перебора

## Быстрый старт

```bash
sudo ./deploy.sh
```

Скрипт выполняет:

1. Проверку наличия Docker и Docker Compose
2. Сборку всех Docker-образов из исходников (`amneziawg`, `xray`, `dns`)
3. Генерацию серверных ключей AmneziaWG, случайных параметров обфускации и случайного UDP-порта (49152–65535)
4. Генерацию `docker-compose.yml` из шаблона
5. Генерацию ключей Xray REALITY X25519 и Short ID
6. Запуск всех сервисов через `docker compose up -d`

В конце скрипт выводит два порта, которые нужно открыть в облачном файрволе.

## Управление клиентами

**Добавить клиента** одновременно в AmneziaWG и Xray:

```bash
./add-client.sh <имя>
```

- Имена клиентов могут содержать только буквы, цифры, дефисы (`-`) и подчёркивания (`_`).
- Для AmneziaWG: создаёт `clients/<имя>_amneziawg.conf` и выводит QR-код в терминал.
- Для Xray: создаёт `clients/<имя>_xray.vless` и `clients/<имя>_xray.png`, выводит VLESS-ссылку и QR-код в терминал.
- Оба сервиса перезапускаются для применения конфигурации. Это быстрая операция, обычно занимает несколько секунд.

**Удалить клиента** из обоих сервисов:

```bash
./remove-client.sh <имя>
```

Контейнеры AmneziaWG и Xray перезапускаются для применения обновлённой конфигурации.

> Отдельные скрипты (`amneziawg/add-client.sh`, `xray/add-client.sh` и т.д.) работают независимо, если нужен только один протокол.

## Цепочка через upstream-сервер для отдельного пользователя (Xray)

Перенаправляйте трафик конкретного пользователя с этого сервера на другой Xray-сервер, в то время как остальные пользователи продолжают выходить локально. AmneziaWG не затронут — chaining работает только в Xray.

```
                         ┌─▶ Интернет  (остальные выходят здесь)
этот сервер ─VLESS/REALITY┤
                         └─▶ upstream Xray ─▶ Интернет  (выбранный пользователь выходит здесь)
```

**Настройка:**

1. На **upstream**-сервере добавьте этот сервер как обычного Xray-клиента и сохраните выведенную VLESS-ссылку:
   ```bash
   ./xray/add-client.sh server1-uplink
   ```

2. На **этом** сервере зарегистрируйте upstream и направьте через него пользователя:
   ```bash
   ./xray/add-upstream.sh <tag> '<vless_url_из_шага_1>'
   ./xray/set-route.sh    <пользователь> <tag>
   ```

   - `<tag>` — алиас для upstream (например, `eu-exit`). Нельзя использовать `direct` и `blocked`.
   - `<пользователь>` — существующее имя клиента (совпадает с полем `email`, которое задаёт `add-client.sh`).
   - VLESS-URL оборачивайте в одинарные кавычки — он содержит `&` и `?`, которые иначе будут интерпретированы shell'ом.

3. Вернуть пользователя на локальный выход:
   ```bash
   ./xray/set-route.sh <пользователь> direct
   ```

При каждой операции контейнер Xray перезапускается; пользователи без персонального правила продолжают выходить через локальный `freedom`-outbound сервера.

## Маршрут DNS

```
VPN-клиент → туннель awg0 (10.8.0.0/24)
  → iptables DNAT (порт 53 → 172.20.0.2:53)
  → dnscrypt-proxy (DNSSEC обязателен, без логов, без фильтрации)
  → Cloudflare + Google (DNSCrypt / DoH)
```

## Как это работает

### AmneziaWG

AmneziaWG — обфусцированный форк WireGuard, который добавляет мусорные пакеты и модификацию заголовков для обхода DPI-блокировок. При развёртывании сервер генерирует случайные параметры обфускации (Jc, Jmin, Jmax, S1–S4, H1–H4), которые вшиваются в конфиги сервера и клиента, делая отпечаток трафика каждого деплоя уникальным.

Управление клиентами требует перезапуска контейнера (обычно несколько секунд). Каждый клиент получает выделенный IP в подсети 10.8.0.0/24 с предварительно согласованным ключом (PSK) для постквантовой прямой секретности.

### Xray REALITY

Xray REALITY делает VPN-трафик неотличимым от легитимного HTTPS-трафика к `cloudflare.com`. В отличие от традиционных TLS-прокси, REALITY не требует домена или сертификата — он заимствует TLS-хендшейк целевого сервера, что делает его практически невидимым для систем цензуры.

Управление клиентами требует перезапуска контейнера (обычно менее 2 секунд). Каждый клиент идентифицируется по UUID и подключается через протокол VLESS с управлением потоком `xtls-rprx-vision`.

### DNS

Все DNS-запросы VPN-клиентов перехватываются через iptables DNAT и перенаправляются на внутренний экземпляр dnscrypt-proxy. Этот резолвер шифрует запросы через DNSCrypt или DNS-over-HTTPS к Cloudflare и Google, требует валидацию DNSSEC и no-logging от вышестоящих резолверов. DNS-контейнер не выставлен на хост — он доступен только внутри Docker-сети.

## Безопасность

- **Сборка из исходников** — amneziawg-go, awg-tools, Xray-core и dnscrypt-proxy собираются из исходников внутри multi-stage Docker-сборок. Никаких готовых бинарников.
- **Файрвол и усиление SSH не автоматизированы** — `deploy.sh` занимается только VPN-стеком. Настройте UFW/iptables, SSH-ключи и fail2ban отдельно (рекомендуется для продакшна).
- **Изоляция ключей** — все ключи генерируются на сервере и никогда не передаются. Файлы ключей имеют права `chmod 600`.
- **Приватность DNS** — DNS-запросы клиентов принудительно перенаправляются на внутренний резолвер через iptables DNAT; они никогда не покидают сервер в незашифрованном виде.
- **Маршрутизация Xray** блокирует соединения к приватным IP-диапазонам (RFC 1918) для предотвращения SSRF.
- Сгенерированные ключи, клиентские конфиги и `docker-compose.yml` добавлены в gitignore и никогда не коммитятся.

## Решение проблем

**Контейнер не запускается:**
```bash
docker compose logs <service>     # Проверить логи
docker compose ps                 # Статус контейнеров
```

**Демон AmneziaWG падает:**
```bash
docker exec amneziawg cat /tmp/awg.log   # Лог запуска демона
docker exec amneziawg awg show           # Статус интерфейса
```

**Клиент не подключается (AWG):**
```bash
docker exec amneziawg awg show awg0      # Проверить наличие пира
```

**Клиент не подключается (Xray):**
- Убедитесь, что порт 443/tcp открыт в облачном файрволе
- Проверьте, что VLESS-ссылка соответствует публичному ключу сервера и Short ID

**DNS не резолвит:**
```bash
docker exec dns drill @127.0.0.1 example.com   # Тест внутреннего DNS
```

**Пересоздать всё с нуля:**
```bash
./cleanup.sh && sudo ./deploy.sh
```

## Удаление

Для полного сброса сервера в чистое состояние:

```bash
./cleanup.sh
```

Запрашивает подтверждение, затем:
- Останавливает и удаляет все контейнеры и Docker-сеть
- Удаляет Docker-образы (`amneziawg`, `xray`, `dns`)
- Удаляет все сгенерированные ключи, серверные конфиги, клиентские конфиги и QR-коды

После очистки `sudo ./deploy.sh` развернёт всё заново с нуля.
